# Figure Art Director V2（图表美术指导）

> 这是图表的视觉合同，不是装饰模板。先确定读者要完成的比较，再决定几何、版式和复杂度；美术理论只负责组织注意力，不能替代数据证据。

## 一、每张主图先写 8 行合同

```text
intent        —— 一句话：这张图要证明哪个可检验结论
reader        —— 读者看完后应能回答什么问题
layout        —— 单轴 / 主图+inset / small multiples / HTML流程 / 2D投影
content       —— 原始点、汇总、模型、区间、阈值、基准、例外中的证据层
color         —— 主色 + 至多两种语义高亮；颜色不是唯一编码
hierarchy     —— 10秒内先看到什么；哪些元素必须降级
annotations   —— 只标阈值、转折、异常、选择、机制；预算通常≤4，复合图≤6
budget        —— 单栏89 mm / 双栏183 mm或竞赛版面比例；按最终缩放设计
```

## 二、从美术与感知理论转译为工程规则

- **接近与对齐**：组内间距小于组间间距；共享坐标、基线、列宽和边缘；不要用一圈边框替代层级。
- **视觉重心**：主证据使用最大有效视觉区域；辅助证据降饱和、降透明度、减小线宽；不通过装饰物制造重心。
- **节奏**：同一组对象保持重复的尺寸、间距和语义色；异常只在数据触发时打破节奏；每个 panel 不要同时改变多个视觉语法。
- **负空间**：留白用于分组、比较和标注缓冲。组间留白至少约为组内间距的1.5倍；四周给标签方向留安全边界；空白不能被无证据元素填满。
- **发现与确认分层**：主图帮助发现整体模式，坐标、区间、短标签或表格帮助确认数值；不要让每个点都承担两种任务。
- **编码优先级**：精确比较优先位置/长度，其次角度，再其次面积；体积和透视只能承担不可替代的空间语义。
- **复杂度退出**：数据不足、重复、高饱和或面板相似时，主动降级为紧凑单图、差值图、例外摘要、inset、表格或附录。
- **黄金比例、三分法等**只作为构图启发，不能改变共享尺度、基线、单位或真实比例。

## 三、图型选择硬规则

- 一张图只服务一个主问题；复合图的每个 panel 必须增加结果、差异、机制、不确定性或决策证据。
- 连续数据使用感知均匀顺序色图；有意义的零点/中心使用发散色图；分类数据使用 Okabe–Ito 等离散色板。颜色之外同时提供 marker、线型、位置或文字。
- 正式图默认纯白背景、深灰文字、淡网格；高饱和色只保留给1–2个关键对象。避免彩虹色、红绿唯一对照、彩色文字和装饰性图标。
- 3D 默认禁用。只有真实空间、时间、轨迹或不可替代的第三连续变量才可使用；必须给出 `geometry_semantics`、视角、遮挡风险和2D投影/切片/离平面残差。离散阶段、类别编号、项目编号不得平滑成曲面。
- 稀疏网格只画真实格点、热图、切片或离散3D；禁止无依据插值、平滑曲面和伪造高分辨率结构。

## 四、Pareto / 多目标专门规则

- 轴标题直接写方向，例如 `成本（↓）`、`收益（↑）`、`风险（↓）`；先统一目标方向，再做非支配判定。
- 先按约束划分 `feasible`、`infeasible`，再在可行解中计算非支配集；不可行候选必须单独表达，不能混入前沿。
- 先去除近重复点并使用尺度相称的浮点容差；记录 `objective_directions`、`feasibility_rule`、`dedup_tolerance`。
- 2D 图可按单调推进的目标排序后连线；3D 纯目标点默认只画散点和投影，不连接无物理顺序的点。
- 背景候选用浅灰低透明度；非支配前沿用单一强调色或深色线；最终选择用统一 `optimum` 角色；不可行用浅灰 `x` 或空心 marker。
- 只标极端点、膝点、基准、最终选择和少数业务候选。默认最多4个标签；必要时用自动避让，标签不得越界或遮住关键点。
- 前沿图应同时让读者看见“可行边界、权衡方向、被支配区域、选择点”；只有一团彩色散点不能称为完整 Pareto 证据。
- 若图只是参数扫描得到的多条响应曲线，标题、文件名和 caption 必须写“响应曲线族/权衡扫描”，禁止误称 Pareto 前沿。

## 五、HTML / SVG 示意图规则

- HTML 是机制、流程和关系图的优先路线：以真实节点、箭头和证据层为中心，不把长段落塞进卡片。
- 先建立显式网格：节点列宽、行高、组间距和箭头锚点固定；流程方向只有一条主路径，旁支降级。
- 每个节点最多标题+一行副信息；详细定义进入 caption、正文或可展开区域；公式拆成可读的短行。
- 使用响应式 SVG/viewBox 或 CSS grid；导出前同时检查论文单栏、双栏和移动宽度。不得依赖缩放后仍可读的微型字体。
- HTML 文字保持深色高对比，背景浅色；关键关系用颜色+线型/箭头表达；不要用渐变、阴影和多色卡片营造“高级感”。
- 形式图必须保留 HTML 源为 canonical；旧的占位 Python 包装器不得覆盖 HTML 产物。

## 六、导出与视觉 QA

- 主文优先 PDF 矢量；Word 使用同次渲染的高 DPI PNG。图内最终字号目标5–7 pt，低于5 pt必须 REVIEW；关键文字必须达到可读对比度。
- 输出后必须通过：PDF文字盒碰撞/越界、最终版面缩放、灰度、颜色可区分性、图例闭环、单位与数据源一致性。视觉模型不可用时保留 REVIEW，不伪装成 PASS。
- PDF 文字盒的微小相交可能来自换行、字体字形边界或浏览器导出文本层；HTML-canonical 图以 `capture.js` 的可见 DOM 几何为主，PDF 文本层碰撞只作 REVIEW。
- 视觉审查发现文字不清、重叠、裁切、3D遮挡、图例遮挡或空/满画布时，先修布局、字号和证据分层，再考虑换模型。
- 每张图必须能追溯到当前 JSON、附件或真实日志；任何代理、占位、手抄或随机重构结果 BLOCK。

```json
{
  "geometry_semantics": "what each axis and visual channel means",
  "objective_directions": ["min", "max"],
  "feasibility_rule": "constraints <= 0 are feasible",
  "annotation_budget": 4,
  "projection_or_residual": "required for 3D when applicable",
  "render_checks": ["pdf_text_geometry", "final_size", "grayscale", "colorblind", "legend_closure", "source_consistency"]
}
```
